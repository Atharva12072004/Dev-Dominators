# Native Services Plan

CyberShield AI will move from Expo Go to Expo development builds with native Android integrations.

## Required Native Android Components

### 1. Notification Listener

Purpose:

- ingest notification text from selected apps
- extract package name, title, body, timestamps, pending intents where available
- send normalized events into the React Native threat pipeline

Android building block:

- `NotificationListenerService`

JS bridge responsibility:

- expose permission status
- start/stop monitoring state
- stream normalized notification events to JS

### 2. SMS Monitor

Purpose:

- receive inbound SMS events
- normalize sender, preview, timestamp, and body
- trigger auto-scan pipeline

Android building blocks:

- `RECEIVE_SMS`
- `READ_SMS` only if historical sync is added
- BroadcastReceiver for incoming SMS

### 3. Accessibility / Link Detection Helper

Purpose:

- best-effort detection of suspicious links being surfaced inside supported apps or browsers
- optionally detect view text / URL-like strings before open events

Android building block:

- `AccessibilityService`

Important:

- high-risk permission from trust and policy perspective
- must be optional, clearly explained, and scoped to link safety use cases

### 4. Warning Activity / Overlay Manager

Purpose:

- present blocking or confirmation UI when a suspicious event is detected
- show risk score, reasons, source app, timestamp
- support `Block and Exit` or `Ignore`

Android options:

- Foreground warning activity: preferred MVP path
- System overlay window: advanced path, policy-sensitive, use only if necessary

Recommendation:

- MVP should use a full-screen warning activity launched by native services
- overlay should remain a later-stage optional enhancement

### 5. URL Guard / Intent Guard

Purpose:

- intercept app-owned links and shared links
- best-effort pre-open scanning before launching browser intents

Android options:

- in-app browser guard
- share target ingestion
- explicit open-intent wrapper inside CyberShield AI

Limitation:

- not a universal OS-level browser interception mechanism

## iOS Strategy

iOS native work should focus on:

- Gmail OAuth
- app-owned browser guard
- local storage/logs
- notifications generated by CyberShield AI itself

Do not promise:

- SMS inbox reading
- third-party notification text monitoring
- overlays on top of other apps
- universal URL interception
